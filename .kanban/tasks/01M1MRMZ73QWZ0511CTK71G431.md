### What

cli-plan.md §11.1, which named a concrete task and gave it no card. It
is the decider for §11.3 — whether the CLI ever needs a shared server —
and the 27B default makes it more likely to matter, not less.

The whole `serve` mode of §11.3, a unix socket transport in the wire
package and a multi-connection agent, exists only if this measurement
says the load cost is real. Measure before building any of it.

**The measurement**, with the shipped defaults and the models already
downloaded:

1. Time `acp-agent run "hello"` from a **cold** page cache. Use
   `sudo purge` between runs, or reboot.
2. Time it from a **warm** page cache — the second and third runs.
3. Split the wall time into resolution and generation, from the
   `ResolutionProgress` phases, so a slow answer is not confused with a
   slow load.
4. Run each case at least three times, and record the median.

Record the numbers in a task comment, and write a one-paragraph verdict:

- **The cost is small** — one binary is correct, `serve` is waste, and
  §11.3 is closed. Say so, and the plan drops the section.
- **The cost is large** — a daemon pays for itself on the second run.
  Then raise the cards §11.3 describes: a socket transport in the wire
  package, and a multi-connection agent.

This is a measurement, not a feature. It writes no product code.

- [ ] Time the cold case, three runs, median
- [ ] Time the warm case, three runs, median
- [ ] Split resolution from generation
- [ ] Record the numbers and the verdict in a task comment

### Acceptance Criteria

- [ ] A task comment holds six timings, the two medians, and the machine
      and model they were taken on.
- [ ] The comment states the resolution/generation split.
- [ ] The comment states one verdict, in one paragraph, and names the
      next step for each branch.
- [ ] No product code changes.

### Tests

This card produces a measurement, so its check is the recorded evidence
and not a unit test. To keep the number honest and repeatable:

- [ ] Add
      `IntegrationTests/Tests/FoundationModelsACPAgentIntegrationTests/ColdLoadBenchmark.swift`,
      a benchmark that runs the timing and prints the split. It asserts
      nothing about the duration — a timing assertion in CI is flaky —
      but it makes the measurement one command instead of a manual
      ritual, so a later reader can repeat it.
- [ ] The benchmark compiles and runs under
      `swift test --package-path IntegrationTests`.

### Blocked by

The new defaults, so the measurement is taken on the profile that ships.
