## What

cli-plan.md §4 and §5.4. This is the product CLI: one prompt in, one
turn, exit.

**The one architecture rule: the CLI reaches the agent through an ACP
connection.** It must never call `RoutedACPAgent` directly. Only the
transport changes between the modes. Break this rule and the later
socket mode becomes a rewrite, and the CLI stops proving the protocol.

In `Sources/acp-agent/RunCommand.swift`:

1. Build the agent with the shared `AgentComposition` of the `acp` task.
2. `InMemoryTransport.pair()` gives two transports. Bind an
   `AgentSideConnection` on one, and a `ClientSideConnection` on the
   other, in one process and with no subprocess. This is the method the
   Mac app uses (`plan.md` §19).
3. Drive the turn from the client side: `initialize`, `session/new` with
   the `cwd`, `session/prompt`, then consume the notifications until a
   stop reason arrives.

Options in this task: `--cwd <path>` and `--resume <session-id>`.
`--cwd` selects **which** dotfolder stack the loader reads, so apply it
before the configuration load, and send the same directory in
`session/new` (§5.10). `--cwd` together with `--resume` is a usage
error: the stored session already has a working directory, and it wins.

`--verbose`, `--quiet`, the stdout rules and the exit codes are separate
tasks. Print the answer plainly here.

- [x] Pair the two connections in process
- [x] Drive initialize, session/new and session/prompt
- [x] `--cwd` before the configuration load, and in `session/new`
- [x] `--resume` through `session/load`
- [x] `--cwd` with `--resume` is a usage error
