## What
`session/resume` of a session that IS live in this process must give the new connection the whole live tree (the session and its in-process sub-agent sessions) and must keep the work going. (User, 2026-11-03: resume must work for in-process sessions along with in-process sub-agent sessions.)

Today (read in the code, not run): `resumeSession` in `Sources/FoundationModelsACPAgent/Agent/SessionResume.swift` (near line 195) tears a live entry down first, like `session/close`: "its open prompts end with `idle(cancelled)`, its Router session closes and its projector stops" (`tearDownSession`), then it restores from disk. The session lifecycle also stops the `AgentRunner` before it closes the root session (`AgentsMount.runner` doc in `Tools/AgentsComposition.swift`), so running sub-agent runs stop too. A hot resume therefore kills the live work.

Do:
1. When the entry is live and not closed, do not call `tearDownSession`. Move the owner with `takeSession` (it exists; the old owner gets no more updates and no more requests, the D120 rule), keep the projectors and the Router sessions.
2. Replay the retained history (`retainedHistory` of each `ActiveSession`) of the root and of each child to the new connection, under their own ids, parent first, with `subagent_update` before child traffic.
3. Pending requests of the tree (permission, elicitation) go to the new owner and are asked once.
4. A running prompt stays open and a running sub-agent run stays running. Confirm with the user before you implement: my reading is that a hot resume of a session with an open prompt keeps the prompt open.
5. The `replayFrom` cursor rules of the existing resume still hold.
6. Do not change the Router or FoundationModelsAgents from this task.

## Acceptance Criteria
- [ ] A hot resume of a root with a running nested sub-agent run keeps the run going, and the run ends normally.

- [ ] A pending child request is asked once, on the new owner.
- [ ] No prompt is cancelled by the resume.
- [ ] A cold resume (nothing live) behaves as before.
