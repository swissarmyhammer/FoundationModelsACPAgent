## Problem

Multitool has a git capability: the read-only verbs `tools.git.blame`, `show`, `log`, `commit`, `status`, `branches`, `changes` and `diff`. Multitool turns git off by default: "A builder that never calls this renders no `tools.git` namespace at all" (`FoundationModelsMultitool/.../Surface/MultiToolBuilder+Capabilities.swift`, `withGit(root:)`).

This agent never calls `builder.withGit(root:)`. `ToolCatalog.swift` calls only `withFiles`, `withShell`, `withWeb` and `withMCP`. Thus, no session of the agent, and no SWE-bench run, has the git tools now. The configuration file also has no `tools.git` section: `ToolSectionCodec.swift:624` knows only `files`, `shell`, `skills`, `codeContext` and `web`.

## Decision

The git tools are ON by default. All the verbs only read, the same as `codeContext` and `web`, which are on by default.

## Change

1. **Multitool pin.** `Package.resolved` pins Multitool at `1155c16`. That revision has `withGit(root:)` and seven verbs. It does not have `tools.git.commit` (b90b7c8), the branch in `tools.git.status` (b2f51b8), or the fix for a failed branch read (80b527e). Move the pin forward to Multitool `origin/main`. Do not use a local `path:` dependency. Do this after task ^jwx92y8 is committed, because that task also changes `Package.resolved`.
2. **Configuration file capability.** Add `GitToolOptions` with one key, `enabled` (default `true`), in `Configuration/ToolSectionCodec.swift`. Use the same pattern as `WebToolOptions`:
   - Add `git` to `ToolsConfiguration.CodingKeys` and to `optionKeys` (line 624), so that an unknown key under `tools.git` is refused.
   - Accept the short form `git: false`, the same as `web: false`.
   - `config init` writes `tools.git.enabled: true`. The written file must read back to exactly the builtin configuration.
   - `config show` and the merge of the dotfolder layers show and merge the key, the same as the other sections.
3. **Mount.** In `ToolCatalog.makeRegistry(context:)`, call `builder.withGit(root:)` with the session working directory when `tools.git.enabled` is true.
4. **Doctor.** If `ToolsDoctor` states the other tool groups, give git a row too. Use `DisabledSectionCheck` when git is off.
5. **README.** Add a `git` row to the § Tools table, and a short section that tells how to set git off.

## Tests

- `ToolSectionCodecTests`: decode `git: false`, `git: { enabled: false }` and no key (default on). An unknown key under `tools.git` is refused. `config init` output reads back to the builtin configuration with git on.
- `ToolCatalogTests`: with the default configuration, the registry renders `tools.git.status` and the other verbs. With `enabled: false`, it renders no `tools.git` namespace.
- One test in a temporary git repository: `tools.git.status` gives the current branch.
