title: The body of the session agent renders with the tool selection of the session agent

## What
Since ^1et93gh, the skills registry of a session gets its template values `tools.<group>.enabled` after the session agent is resolved, thus a skill and the `skills:` preload follow the `tools:` and `disallowedTools:` keys of the session agent.

The body of the session agent itself does not follow. `AgentRunner.sessionAgentInstructions(for:)` renders the body with `AgentBodyRenderer`, which reads `AgentRegistry.templateContext`. The session resolves its agent from that registry, thus the registry is made before the selection is known (`AgentsComposition.makeAgentRegistry` uses the values of the configuration). A body with `{% if tools.shell.enabled %}` thus tells the steps of a tool that the session does not have.

Also: the agent runs share the one skills registry of the session (one `AgentEnvironment`). After ^1et93gh a run sees the values of the root session agent, not the values of its own tools. The pinned packages give no per-run template context.

- [ ] A session agent with no `tools:` key renders its body with the same values as today.
