## What
Decision D125 (c), spec ACPA-16 (TestudoApp/features/packages/foundationmodels-acpagent.md). Request from testudoapp-75 (2026-11-10). The app gives `<iCloud container>/Projects/`, which is outside `Documents/`, so the Files app does not show it. TestudoApp connects it in a follow-up card.

Today `AgentHome.projectsDirectory` (`Sources/FoundationModelsACPAgent/Configuration/AgentHome.swift` ~194) is always `<synced>/projects/`.

1. `AgentHome.swift`: add a stored property `projectsDirectory: URL`, set by each factory. Remove the computed property.
2. `makeCustom(synced:local:)` becomes `makeCustom(synced:local:projects:)`. `projects:` is required, with no default value (the package has no backward compatibility rule).
3. `makeXDG(name:environment:)` keeps `<synced>/projects/`.
4. `Sources/acp-agent/AgentComposition.swift` `home(environment:)` (~125): pass `folder/<synced>/projects`, which is the same folder as today.
5. Change the doc examples in `ComposedAgent.swift` (~28, ~111) and the test callers: `Tests/FoundationModelsACPAgentTestSupport/AgentHomeFixture.swift`, `AgentHomeTests.swift`, `HomeOptionsTests.swift`, `Doctor/HomeDoctorTests.swift`.
6. The users (`SessionSetup.swift` ~873 `ProjectStore(directory: home.projectsDirectory)`, `SessionList.swift` ~82 and ~99, `RegisteredRecordingRoots.projectsDirectory(of:)`, `TranscriptStore`) need no change, because they read `home.projectsDirectory`.

Both must agree, because the CLI's `ACP_AGENT_HOME` home and the library's XDG preset must place the project store in the same folder. Two copies of one value can drift apart. Expose the library constant to the CLI, for example by making `AgentHome.projectsFolderName` public, and delete `AgentComposition.projectsFolderName`.
