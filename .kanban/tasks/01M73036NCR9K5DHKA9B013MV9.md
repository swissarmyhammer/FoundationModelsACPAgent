## What
Spec: ACPA-1 (TestudoApp/features/packages/foundationmodels-acpagent.md). Decision D90 (c).

After ACPA-1a, the session knows its agent (`AgentDefinition`). This task applies its frontmatter to the root session:
1. `tools:` and `disallowedTools:` (`AgentDefinition.tools`, `.disallowedTools`, `ToolSpec`): filter the capabilities of the session surface in `Sources/FoundationModelsACPAgent/Tools/ToolCatalog.swift` (`sessionSurface`). Use the same `ToolSpec` match that a sub-agent run uses in FoundationModelsAgents, so a root session and a run read a list the same way.
2. The endpoint tools cannot be removed (D90 c): `agents`, `skills`, `sessions`, `kanban`, `rules` and `runCode` (which gives `files`). Keep one list of these names in `ToolCatalog.swift`. When an `AGENT.md` names one of them in `disallowedTools:` or leaves it out of `tools:`, the tool stays, and the session logs one warning.
3. `model:`: the model slot of the agent is the start value of the `model` config option (`ConfigOptions.swift`, `selectableSlots`). An unknown slot logs a warning and uses `defaultSlot`.

## Acceptance Criteria
- [ ] A session agent with `tools: [web]` has `web` and every endpoint tool, and no other capability.
- [ ] A session agent with `disallowedTools: [agents, shell]` has no `shell`, and still has `agents`, with one warning.
- [ ] A session agent with `model: flash` starts on the flash slot, and the `model` option shows `flash`.
- [ ] A session agent with no `tools:` has the full surface, as today.

## Tests
- [ ] `Tests/FoundationModelsACPAgentTests/SessionAgentToolsTests.swift`: one test for each criterion above.
- [ ] `swift test` passes with no warnings.
