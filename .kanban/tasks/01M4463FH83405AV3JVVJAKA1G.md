title: Four multi-fixture tests pass the 60 s time limit in a parallel `swift test` run on a loaded machine
---
## Why

On 2026-10-04, with the machine load average at 30 to 62 on 32 cores (sourcekit-lsp index builds of other packages), a parallel `swift test` run failed these four tests with "Time limit was exceeded: 60.000 seconds":

- `SessionResumeTests.replayFromStartSendsWholeMessageUpsertsWithTheLiveIds()`
- `SessionResumeTests.aNewAgentReplaysTheMessagesWithTheIdsOfTheEarlierAgent()`
- `CompactionReportTests.aResumeReplaysTheCompactionEntryAndTheEarlierMessages()`
- `BuiltinCommandsTests.noBuiltinInvokesTheModelBackend()`

HEAD 2f8aeff (no local source change) fails the same four tests in the same way. `swift test --no-parallel` passes all 737 tests.

Measured time of one resume test: 1.4 s alone, 2.4 s with its suite (12 tests), 22.7 s with three suites (44 tests), more than 60 s in the full run (737 tests). The four tests in the 44-test run all ended at the same time (22.7 s). Each test makes two or more agent fixtures in sequence, and each fixture starts a CodeContext index pass and an embedding pass.

## What to do

- Find the shared resource or the CPU cost that makes these tests scale with the number of tests that run at the same time.
- Make the tests pass in a parallel run on a loaded machine, with no sleeps and no larger time limit as the only fix.
