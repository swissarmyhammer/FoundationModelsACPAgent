## Added 2026-07-28: `/config` and `/config export`

Defaults now live in code with no shipped `config.yaml` (plan §4), so the agent must be able to write one on request — a default you cannot see is a default you cannot change. New builtin `.action`:

- **`/config`** — print the effective merged configuration as commented YAML to the session. Read-only, no file written. This is the default with no arguments.
- **`/config export home`** → `~/.config/<name>/config.yaml`
- **`/config export project`** → `<session cwd>/.<name>/config.yaml`

The emitter itself belongs to `AgentConfiguration` (task esq54zr); this task owns the command, its argument parsing, and its safety.

**Writing a file is a side effect, and this is the one builtin that has one.** Rules:

- If the target exists, **refuse and say so**; overwrite only on an explicit `--force`. A hand-edited config silently replaced by a machine-generated one is exactly the failure that makes people stop trusting a tool.
- Create the containing directory when absent — that is not destructive.
- Report the absolute path written, so the user knows which layer they just pinned.
- An invalid or missing destination argument errors with the two valid values; never guess a location.

`argumentHint` maps to ACP's `AvailableCommandInput` `{type: "text", hint: …}` (the `type` discriminator is required in v2). Consider a symmetric `/instructions export home|project` for the compiled-in system prompt (§6.0) — same problem, same shape.

Tests:

- [ ] `/config` prints without writing anything.
- [ ] `/config export home` writes to the user layer; `project` writes to the project layer under the session's cwd, not the process cwd.
- [ ] An existing target is refused; `--force` overwrites.
- [ ] The written file decodes back to the same effective config (round-trip through the real command).
- [ ] A bad destination argument errors and names the valid values.
- [ ] No model turn and no transcript entries beyond what the action records.
