## What
ACPA-15: a `timelineConflict` (another process wrote the timeline) or a `workingDirectoryMismatch` (a moved project) is logged, and the session continues with no snapshots. It does not stop the agent.

`SnapshotHook` of FoundationModelsHooks (`SnapshotHook.swift`, `log` at line 113) already logs the errors of `open` on `SessionStart`. But ACPAgent has no test for this, and the `snapshots` capability of Multitool (`SnapshotsCapability`, added in `ToolCatalog.makeRegistry`, `ToolCatalog.swift:434-436`) must give a clear answer when the key is not open, not an error that stops the turn.

Do this:
- Make sure that a session whose key open failed still runs its turns, and that `tools.snapshots.*` gives a clear message ("snapshots are not available for this session: <case>") and not a crash. If the message comes from Hooks or Multitool and is not clear, do not change those packages: write a card on the board of that package (see memory "Stop before Router changes").
- Make sure the log line names the key and the error case, with no file content.

## Acceptance Criteria
- [ ] A session with a `workingDirectoryMismatch` runs a turn to the end.
- [ ] A session with a `timelineConflict` runs a turn to the end.
- [ ] One log line names the key and the error case.

## Tests
- [ ] A test: make a timeline for a key with working directory A, then start a session with the same key in working directory B. The turn ends normally, and a `tools.snapshots.list` call gives a message, not a thrown error.
- [ ] A test for `timelineConflict` with a second `SnapshotStore` that writes the ref of the same key.
- [ ] `swift test` passes with zero failures and zero warnings.

## Workflow
- Use `/tdd` — write failing tests first, then implement to make them pass. #acpa-15
