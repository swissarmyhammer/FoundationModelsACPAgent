### What

cli-plan.md §5.9. `Ctrl-C` must not kill the process.

In `Sources/acp-agent/InterruptHandler.swift`:

1. A `DispatchSourceSignal` for `SIGINT`, with the default disposition
   ignored so the process does not die. **The handler body only sets an
   atomic flag and resumes a continuation** — a signal handler must be
   async-signal-safe, so it calls nothing else. The real work happens on
   a normal task that waits on that continuation.
2. First signal: send `session/cancel`, wait for the `cancelled` stop
   reason, print the text that already arrived, exit 4.
3. Second signal: end the process at once.

**Confirm before you build the download case.** cli-plan §5.9 claims the
first `Ctrl-C` stops a resolution. The resolution runs inside
`RoutedACPAgent.init` → `router.resolve(profile:reporting:)`, and
nothing in this repository verifies that Router honors Task
cancellation there. Check it first:

- If Router's resolve is cancellable, write the download case as stated,
  and assert that the partly downloaded files stay in the Hugging Face
  cache — remove nothing on the way out.
- If it is **not** cancellable, say so in a task comment, drop the
  download claim from this card, and raise a Router card for it. Do not
  ship a plan that promises to interrupt a 15 GB download when the
  runtime cannot.

- [ ] The `SIGINT` source; the handler body only sets a flag
- [ ] First signal: cancel, wait, print, exit 4
- [ ] Second signal: end at once
- [ ] Confirm Router's resolve cancellation, and record the answer

### Acceptance Criteria

- [ ] A `session/cancel` reached the agent before the exit.
- [ ] The `DispatchSourceSignal` handler body sets a flag and calls
      nothing else.

      and this card's scope matches the answer.
