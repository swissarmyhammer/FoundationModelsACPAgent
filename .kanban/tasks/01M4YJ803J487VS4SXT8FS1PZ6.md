Found by Multitool, sent by the step lead (swissarmyhammer-96).

Problem: the test waits for the exit event of each server process (ProcessExitWatch.waitForExit), and then runs pgrep again and reads ProcessExitWatch.hasExited for each pid. That second read can say "not exited" after a correct exit:
- The kernel sends NOTE_EXIT before it sets SZOMB, so for a short time the process is not gone and not a zombie.
- The parent can reap the pid, and the system can give the pid to a new process.

Fix (the same as Multitool):
- The end of the wait is the result. Remove the second pgrep and read after the wait.
- The read before the wait (hasExited) also counts a process that has P_WEXIT set (it is in exit). It reads p_stat and p_flag with sysctl KERN_PROC_PID.

Check: one full root run, green. #tests #mail-step-4
