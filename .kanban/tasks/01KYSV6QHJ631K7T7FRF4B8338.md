## What
Plan.md §4.1–§4.4. Create `Sources/FoundationModelsACPAgent/Transcripts/`:

- `TranscriptLocation.swift` — resolve the recording root from `transcripts.location`. `project` (the default) gives `<cwd>/.<name>/transcripts/`. `home` gives a shared root with the `-Users-…` slug scheme. An absolute path is used as given. The resolved root is what `makeSession(recordingRoot:)` receives.

**The on-disk layout, confirmed against Router:**
- With `recordingRoot` set, a session directory is `<recordingRoot>/<sessionId>/`.
- **A fork nests inside its parent's directory, and the nesting IS the lineage record.** No file stores a parent path.
- Identity is the directory name, and it must parse as a ULID.
- A directory is a session only if it holds `session.json`.
- `session.json` is write-once.
- **`transcript.jsonl` fsyncs only after a `.response` event, so the final line can be torn after a crash.** A reader drops a torn final line with a warning. A corrupt earlier line throws. Match that rule in our own readers.
- `seq` is global across directories, and a merge sorts by `(ts, seq)`.

- `SessionIndex.swift` — `sessions.jsonl`, append-only, one self-contained record per line. A record carries `sessionId`, `cwd`, the generated `title` (the first user prompt cut to one line), `updatedAt` (RFC 3339), and the complete ordered `additionalDirectories` list. Never persist client-supplied `mcpServers`; headers carry bearer tokens and this file is committed. The index must rebuild from a scan of session directories, because a damaged index is not load-bearing.

- On the first write into a project's transcripts directory, make `transcripts/.gitattributes` with `linguist-generated=true` on `transcripts/**` and `merge=union` on `sessions.jsonl`. Nothing under `.<name>/` is ignored. There is no redaction anywhere.

- `ProjectRegistry.swift` — `~/.config/<name>/projects.jsonl`. Append `{path, firstSeen, lastSeen}` when a session starts in a new cwd. Paths only, never content. Skip stale entries on read.

**Recording level correction: `RecordingLevel` has only two cases, `off` and `full`. There is no `metadata` level.** The old task text and plan §4.3/§4.4 offered `metadata` as a repo-size escape hatch. It does not exist. The only choice is full recording or none. Default to `full`.
