## What
When an agent run starts, send one `subagent_update` on the PARENT ACP session. It must go out before any request or event that uses the child id (RFD rule: the agent must not guess parentage and must not move an issued interaction to an other session).

Fields: `update.sessionId` (child id from `SubagentSessionTable`), `title` (agent name), `description` (agent description), `capabilities: { cancel: {} }`, `state`, `cwd`, `additionalDirectories`. Later sends carry only changed fields. An omitted field is unchanged and `null` clears it.

Hook: `AgentsComposition.makeRunEventObserver` (`Sources/FoundationModelsACPAgent/Tools/AgentsComposition.swift`) today only calls `runCallJoins.recordAgentRunEvent`. Add the announce there, or in a new `SubagentAnnouncer` in `Sources/FoundationModelsACPAgent/Agent/SubagentAnnouncer.swift`. The observer is synchronous and must not wait, so the announcer hands the send to an ordered async queue that keeps the order: announce first, then events.

Needs: the wire type `SessionUpdate.subagentUpdate` does not exist in FoundationModelsACP yet (the generated `SessionUpdate` union has no such case). That is a change in a sibling package. Do NOT add it from this task. Wait for the card on FoundationModelsACP (to be discussed with the user first), or use a local type if the user decides so.

- [ ] The first wire message that carries a child id is a `subagent_update` for that id, on the parent session id.

- [ ] A second event of the same run sends no second full announcement; a changed `state` sends a patch.
- [ ] No announcement is sent when the connection is closed or the session is closed.
