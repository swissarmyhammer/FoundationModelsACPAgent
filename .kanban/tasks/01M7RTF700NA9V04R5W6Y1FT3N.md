title: Some HotResumeTests do not cancel the open prompt task of the tree when a step throws
---
## Problem

`HotResumeTests.openPrompt(of:hold:)` starts an unstructured `prompt` task and keeps it in `LiveTree`. Some tests cancel it with `defer { tree.prompt.cancel() }`. Other tests do not, for example `aHotResumeDoesNotCancelTheOpenPrompt`, `theReplayAnnouncesTheChildBeforeItsHistory`, `theWireOfAHotResumeFollowsTheRulesOfTheValidator`, `theNewConnectionOwnsTheRootAfterAHotResume`, the tests on `startAskingTree()`, and the two tests of a failed hot resume. In these tests, when a step before `finish(_:observedBy:)` throws, the prompt task stays and the fixture does not close. This is the `swift/concurrency` rule: do not leak an unstructured `Task`.

Found during ^s421j3d. That card changed only the reader of `resumeTrace(of:on:)`.

## Work

- [x] Make sure that each test of `HotResumeTests` cancels the prompt task of its tree on each exit path, with one shared shape (for example a `defer` in each test, or a helper that owns the tree and cancels the prompt).
- [x] Do not change what the tests check. #acpa-6
