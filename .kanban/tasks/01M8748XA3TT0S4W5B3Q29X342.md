## Problem

Brief: .briefs/FoundationModelsACPAgent-spotlight-content-catalog-2026-11-24.md, part 4. The host has no read of the agents, the skills, the rules and the MCP servers for Spotlight.

## Fix

- `LibraryContentCatalog` (`contentCatalog.library`). A domain (`LibraryDomain`) is one kind (`agent`, `skill`, `mcpServer`) at one level (`user`, or `folder(URL)` of a known folder). The known folders are the folders of the sessions of the directory that `readableFolder` permits.
- `LibraryContentRecord`: id (domain and name), displayName, description, body, isEnabled, transportKind. An MCP server record has no command, no argument, no URL, no environment value and no header.
- `stamps()`, `records(of:)`, `record(_:)`, `changes()`. A read of a domain starts its watch: a file watch of the layer root for agents and skills, a watch of `tools.mcp` in the settings store for MCP servers.
- Rules: no records. No reader of rules exists yet (FoundationModelsRules has only its plan). Testudo decided on 2026-11-24 to wait for that reader. The folders of rules follow D63; see the card for the rules folders.

## Tests

`LibraryContentCatalogTests`: a skill of a folder gives a record at the folder level and a stamp; an agent gives its description and body; an MCP server record holds no secret; a refused folder gives no record; a new skill gives a change with each record.
## Result

Done as planned. The full suite passed (2874 tests, 1 known issue).
