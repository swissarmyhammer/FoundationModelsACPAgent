### What

The agent does the whole job through `acp-agent run`. The tier-4 eval,
on the same model and the same machine, makes no token at all. So the
defect is in the eval harness and not in the product.

### Measured on 2026-09-08, on `mlx-community/Qwen3.8-27B-mxfp4`

**The CLI works.** `acp-agent run --verbose --cwd <dir> "Read the file
marker.txt and tell me exactly what it says."`

```
EXIT=0
stdout: `marker.txt` contains exactly one line:
        ```
        hello from the probe
        ```
stderr: tool call_… completed searchTools
        tool call_… completed runCode
        tool call_… completed wait
        (twice over)
        stop end_turn
```

It read a real file, ran the whole `searchTools` to `runCode` to `wait`
chain, answered correctly, and left with exit 0.

**The eval hangs.** The same model, driven by
`PythonCLIEvaluationTests`, made no fragment at all:

```
session 01M2176C6N076KW9APHRCY0H0M:
generation has produced no fragment in 390.1s (0 so far, 390.1s in flight)
```

A run under the `4bit` default hung the same way for 3120 seconds. The
`4bit` default was a true defect and `^s0bw5cv` corrects it, but this
card is a SECOND defect: `mxfp4` answers through the CLI and still hangs
under the eval.

### What to do

Find what the eval does that the CLI does not. Read
`IntegrationTests/Tests/FoundationModelsACPAgentIntegrationTests/Evaluations/`
— `PythonCLISubjectHost` composes its own `Router`, its own
`RoutedACPAgent` and its own configuration, so it is a second wiring of
the same parts and the two have drifted.

Candidates, to test in order:

1. **The prompt.** The CLI probe sent one short sentence. The eval sends
   a build task. Send the eval's own prompt through the CLI. If the CLI
   hangs on it, the prompt is the difference and the harness is clear.
2. **The composition.** The eval sets `recordingsDir`, writes its own
   user config, and constructs `Router` and `RoutedACPAgent` by hand.
   The CLI goes through the shipped composition path. Compare them, key
   by key, and name every difference.
3. **The process.** The eval runs inside `swift test` with
   `MetalLibraryTestBootstrap`. The CLI runs as a plain binary. Prove
   whether the shader-library bootstrap changes generation.

- [ ] Name the one difference that makes the eval hang
- [ ] Make the eval drive the model the same way the CLI does
- [ ] Prove one eval sample answers with a stop reason and real tokens

### Acceptance Criteria

### Tests

### Why this is separate from `^s0bw5cv`

`^s0bw5cv` is the wrong default: the `4bit` build does not generate for
anybody. This card is the harness: `mxfp4` generates for the CLI and not
for the eval. Do not let one hide the other.
