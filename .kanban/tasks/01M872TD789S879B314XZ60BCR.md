## Problem

Brief: .briefs/FoundationModelsRouter-reasoning-order-2026-11-24.md. A pass R1, tool call, R2, text A gives the journal in the right order, but the wire (and thus the history file and the replay) is thought R1, tool call, message A, thought R2.

## Cause

Router sends the reasoning of a fragment (`ResponseFragment.reasoning`) before its text. The live SDK backend fills it from the snapshot. `ScriptedSessionBackend` gave only a `String` stream, so its fragments had no reasoning. R2 then went out from the transcript watch or from the end-of-submission diff, after A. A Router read of the backend transcript before each text is not safe for the SDK backend (it aborts between tool-loop passes).

## Fix

`ScriptedSessionBackend.streamResponseFragments` gives each text delta as a fragment with each reasoning entry of the pass whose text changed (the entry id is the id of the `.reasoning` entry). Router then sends R2 before A, by construction.

## Test

`LiveThoughtOrderTests`: the live updates and the resume replay are thought R1, tool call, thought R2, message A. It failed before the fix with the order of the brief.
## Result
