## What
Request from testudoapp-75 (2026-11-10). On the real agent, a new `Agents/<id>/AGENT.md` that Finder or iCloud writes never reaches the `agents` endpoint. The change subscription stays open with no event, and a new query lists only `default`.

Cause: `AgentsComposition.makeAgentRegistry` (`Sources/FoundationModelsACPAgent/Tools/AgentsComposition.swift`, doc ~66 "It does not watch") makes the `AgentRegistry` with the default `watch: false`. The skills registry already watches (`ToolCatalog.makeSkillsSource`, `SkillsRegistry(stack:watch: true ...)`).

Decision (choice 1 of testudoapp-75): give `watch: true` to the agent registry. The `DotfolderWatcher` of FoundationModelsAgents then watches each local layer root (the root settings folder and the project layer) and publishes each new catalog. An iCloud download writes the file into the folder, so FSEvents sees it. A placeholder that is not downloaded is not a file yet; the NSMetadataQuery of the app (TestudoApp ^vh559mp) asks for the download.

1. `AgentsComposition.makeAgentRegistry`: pass `watch: true`. Change the doc comment: the registry watches, and the catalog of the endpoint changes; the schema of the `agents` tool for the model stays fixed for the session, so a new agent reaches the model in the next session.
2. Confirm that the `agents` GraphQL endpoint reads the current catalog (`catalog()` or the catalog updates), not a copy taken when the session started. If it reads a copy, make it follow the catalog updates of the registry, and send a change event.
3. Confirm that the watcher stops when the session closes (the surface shutdown). A closed session must leave no watcher.
