## Dependency (not on this board)

Router ^abrxfy5 (01M7T179V2HYWNY596CABRXFY5), in work. It gives:
1. a public pure `SessionSummary.init(record: SessionRecord)` that uses the same code as the directory (one slug rule);
2. a public static `RouterSessionDirectory.recordedSummary(inSessionFolder: URL) throws -> SessionSummary?` that reads only that folder's index.md (nil when the folder has no index.md).
The names can change a little in the Router review; wait for the final names and the sha.

## Current behavior

The reconcile of the transcript search index (`Search/TranscriptSearchApplier+Reconcile.swift`, `Search/TranscriptSessionMetadata.swift`) builds the session facts of each recorded session from its `index.md` record. It cannot use `summary(of:)`, because for a closed session that function reads every registered project folder, also folders that the process cannot read. The Router function that turns a record into a `SessionSummary` was internal, so the agent COPIED the slug rule (title slug, else the 7-character short id).

## Change

1. Use `recordedSummary(inSessionFolder:)` (or `SessionSummary(record:)`) in the reconcile.
2. Remove the copy of the slug rule and any other copied record-to-summary code.
3. Keep the rule: read only folders that the host says are readable.

## Tests

- The session item of a recorded session in the reconcile has the same name, slug and facts as `summary(of:)` gives for a live session.
- A session with no title gets the slug of the Router (the short id), from the Router function. #d207 #search
