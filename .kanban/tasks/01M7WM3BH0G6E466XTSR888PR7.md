## Problem

- `ACPEventTranslator.closeCancelledRun(of:)` (ACPEventTranslator.swift:266-278), sent by `SessionProjector.closeUnfinishedCalls(of:status:answerStopped:)` (SessionProjector.swift:804-813), and `SessionProjector.closeDetachedCalls()` (SessionProjector.swift:774-779) send a final `cancelled` status for a detached call with no settlement.
- `BackgroundWatch.changes(afterSending:)` reports `.callSettled` only for a run with `isSettling` (BackgroundWatch.swift:155). Only a `runSettled` event of kind `completed` sets `isSettling` (BackgroundWatch.swift:96-99). After a cancel, Router drops the settlement.
- Thus `BackgroundBook` keeps the call in `detachedCalls`. Each later `state_update` lists it, and `SessionStateLedger.noteActivity()` (PromptState.swift:422) keeps the session active. A parent then lists the child as background work.

## Work

1. When the agent sends a final status for a detached call that has a run in the watch, report `.callSettled` for that call after the update went out, and remove the run. Then the ledger sends the state again with the shorter list.
2. Keep the order: the final `tool_call_update` first, the shorter `state_update` after it (BackgroundWatch.swift:84-88, BackgroundBook.swift:6-7). Do not change it.
